# G-Cubed Build Switcher Devcontainer Matrix

The default `.devcontainer/devcontainer.json` remains the source-development
container: it installs this checkout in editable mode and installs npm
dependencies for the extension.

The matrix configs are customer-like test containers. They download a selectable
Python artifact and a selectable VSIX into
`/home/vscode/extensions/gcubed-venv-switcher`, then the setup script installs
the Python side from that artifact instead of the editable checkout.

## Flavours

| Config | Purpose |
| --- | --- |
| `.devcontainer/matrix-legacy/devcontainer.json` | Tests the legacy Microsoft Python extension path. |
| `.devcontainer/matrix-python-envs/devcontainer.json` | Tests the `ms-python.vscode-python-envs` path. |
| `.devcontainer/matrix-active/devcontainer.json` | Generated by `scripts/devcontainer-profile prepare`; ignored by git. |

## How The Wrapper Works

`scripts/devcontainer-profile` turns a named profile into a concrete active
devcontainer config. The generated config writes the chosen Python artifact,
VSIX artifact, and Python extension mode directly into
`.devcontainer/matrix-active/devcontainer.json`.

That active config is intentionally ignored by git. It is a local test fixture,
not source truth. Regenerate it whenever you want to test a different artifact
combination.

This is safer than relying on VS Code inheriting host shell environment
variables, especially when VS Code is already running or launched from Windows
into WSL.

## Quick Start

List the supported profiles:

```bash
scripts/devcontainer-profile list
```

Generate the active devcontainer config for the current live release shape:

```bash
scripts/devcontainer-profile prepare legacy-baseline
```

Then in VS Code, run `Dev Containers: Reopen in Container` and choose the
generated active profile:

```text
G-Cubed Build Switcher Matrix - Active Legacy (legacy-baseline)
```

If the standalone `devcontainer` CLI is installed and working, this does the
same preparation and then starts the container from the command line:

```bash
scripts/devcontainer-profile up legacy-baseline
```

If `up` fails because the devcontainer CLI is missing or unhappy, the active
profile has still been generated. Use the VS Code command palette flow above.

## Command Reference

| Command | Use |
| --- | --- |
| `scripts/devcontainer-profile list` | Show the available migration profiles. |
| `scripts/devcontainer-profile show <profile> [options]` | Summarise the selected profile without writing files. |
| `scripts/devcontainer-profile render <profile> [options]` | Print the generated devcontainer JSON to stdout. |
| `scripts/devcontainer-profile prepare <profile> [options]` | Write `.devcontainer/matrix-active/devcontainer.json`. |
| `scripts/devcontainer-profile up <profile> [options]` | Prepare, then run `devcontainer up` when the CLI is available. |
| `scripts/devcontainer-profile env <profile> [options]` | Emit `export ...` lines for the older `${localEnv:...}` matrix configs. |

## Usage Examples

Baseline: current live Python artifact, current live VSIX, legacy Python
extension path.

```bash
scripts/devcontainer-profile prepare legacy-baseline
```

Test a new Python wheel against the current live VSIX and old Python extension
path:

```bash
scripts/devcontainer-profile prepare new-python-old-vsix \
  --python-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed_build_switcher-1.2.3-py3-none-any.whl"
```

Test the current live Python artifact against a candidate VSIX, still using the
legacy Microsoft Python extension path:

```bash
scripts/devcontainer-profile prepare old-python-new-vsix-legacy \
  --vsix-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed-vscode-venv-switcher.vsix"
```

Test the candidate Python wheel and candidate VSIX together, using the legacy
fallback path:

```bash
scripts/devcontainer-profile prepare new-python-new-vsix-legacy \
  --python-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed_build_switcher-1.2.3-py3-none-any.whl" \
  --vsix-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed-vscode-venv-switcher.vsix"
```

Test the current live Python artifact against a candidate VSIX using the new
Python Environments extension path:

```bash
scripts/devcontainer-profile prepare old-python-new-vsix-python-envs \
  --vsix-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed-vscode-venv-switcher.vsix"
```

Test the candidate Python wheel and candidate VSIX together, using the new Python
Environments extension path:

```bash
scripts/devcontainer-profile prepare new-python-new-vsix-python-envs \
  --python-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed_build_switcher-1.2.3-py3-none-any.whl" \
  --vsix-url "https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/gcubed-vscode-venv-switcher.vsix"
```

Preview exactly what the generated profile will contain without writing the
active config:

```bash
scripts/devcontainer-profile render new-python-new-vsix-python-envs \
  --python-url "https://example.invalid/gcubed_build_switcher-1.2.3-py3-none-any.whl" \
  --vsix-url "https://example.invalid/gcubed-vscode-venv-switcher.vsix"
```

Emit the raw environment exports for the original matrix configs that still use
`${localEnv:...}` selectors:

```bash
eval "$(scripts/devcontainer-profile env legacy-baseline)"
```

`prepare` is usually the safer workflow because the artifact choices are written
into `.devcontainer/matrix-active/devcontainer.json`, so they do not depend on VS
Code inheriting the shell environment.

## Artifact URL Notes

The matrix Docker build uses `curl` inside the container build, so explicit
artifact URLs must be reachable from inside Docker without interactive
authentication.

Good candidates:

- GitHub release asset URLs, such as
  `https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/latest/download/<asset>`.
- Moving secure channel tag URLs for the new bundle path, such as
  `https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/download/latest-secure/<asset>`.
  This is intentional in the short term so field deployments can pick up the
  approved secure bundle without per-template edits.
- Immutable release tag URLs, such as
  `https://github.com/McKibbin-Software-Group/gcubed-build-switcher/releases/download/v1.2.3/<asset>`, once field upgrade mechanics are ready for that model.
- A short-lived internal URL that does not expose secrets in the command or build
  logs.

Avoid putting tokens in artifact URLs. Docker build args and build logs are too
easy to leak.

GitHub Actions artifacts are useful for inspection, but they are awkward as
matrix inputs because downloading them usually requires GitHub API
authentication. For full matrix validation, prefer publishing candidate wheel
and VSIX assets to a draft, prerelease, or internal test release.

## What To Check After Rebuild

Inside the rebuilt devcontainer, confirm the artifact pair and switch path:

```bash
ls -lah /home/vscode/extensions/gcubed-venv-switcher
python -c "import gcubed_build_switcher as g; print(g.__version__)"
```

Run a real switcher smoke test when a configured build tag is available:

```bash
gcubed-switch <build_tag>
```

For the VS Code side, watch the extension logs or live socket smoke output:

- Legacy profile responses should succeed through the legacy Python extension
  API path.
- Python Environments profiles should return or log `apiId:
  "ms-python.vscode-python-envs"` when the new API path is used.
- If the new API is unavailable, the candidate extension should fall back to the
  legacy API and report that fallback clearly.

## Artifact Selectors

Set these in the host shell before rebuilding a matrix devcontainer, or let
`scripts/devcontainer-profile prepare` write them into the generated active
profile for you:

| Build arg | Purpose |
| --- | --- |
| `VENV_SWITCHER_TAG` | Backward-compatible tag used for both halves when the specific selectors are unset. Defaults to `latest`. |
| `VENV_SWITCHER_PYTHON_TAG` | Release tag for the Python artifact only. |
| `VENV_SWITCHER_PYTHON_URL` | Full URL for the Python artifact only. Overrides `VENV_SWITCHER_PYTHON_TAG`. |
| `VENV_SWITCHER_PYTHON_FILE` | Destination/release filename for the Python artifact. Use `pyproject.toml` for the old shape or the wheel filename for wheel testing. |
| `VENV_SWITCHER_VSIX_TAG` | Release tag for the VSIX only. |
| `VENV_SWITCHER_VSIX_URL` | Full URL for the VSIX only. Overrides `VENV_SWITCHER_VSIX_TAG`. |
| `VENV_SWITCHER_VSIX_FILE` | Release asset name for the VSIX. Defaults to `gcubed-vscode-venv-switcher.vsix`. |

The setup script installs the Python side from `*.whl` when a wheel artifact is
present. Otherwise it falls back to `uv pip install --system -r pyproject.toml`,
which preserves the old release path.

## Migration Matrix

| Profile | Config | Python artifact | VSIX artifact | VS Code Python mode |
| --- | --- | --- | --- | --- |
| `legacy-baseline` | `matrix-legacy` | current release `pyproject.toml` | current release VSIX | legacy `ms-python.python` |
| `new-python-old-vsix` | `matrix-legacy` | candidate wheel | current release VSIX | legacy `ms-python.python` |
| `old-python-new-vsix-legacy` | `matrix-legacy` | current release `pyproject.toml` | candidate VSIX | legacy fallback |
| `new-python-new-vsix-legacy` | `matrix-legacy` | candidate wheel | candidate VSIX | legacy fallback |
| `old-python-new-vsix-python-envs` | `matrix-python-envs` | current release `pyproject.toml` | candidate VSIX | `ms-python.vscode-python-envs` |
| `new-python-new-vsix-python-envs` | `matrix-python-envs` | candidate wheel | candidate VSIX | `ms-python.vscode-python-envs` |

The first two rows prove the new Python side remains compatible with the live
extension. The later rows prove the candidate extension works with both Python
generations and both Microsoft Python environment paths.
